### 4. How the Analyst Should Work

The Analyst does **not** make a single LLM call. It runs a 4-phase pipeline:

1. **Memory Consultation & Query Planning:**
   - Checks `EntityMemory` for any entities mentioned (e.g., if the user asks *"Which of those companies raised funding?"*, it resolves *"those companies"* to Zepto, Blinkit, Instamart from memory).
   - Generates a structured research plan: 2–4 targeted search queries, identifying what facts are needed (e.g., store count in 2022 vs. 2024).
2. **Parallel Search & Evidence Gathering:**
   - Fires search queries concurrently via `asyncio.gather`.
   - Deduplicates URLs and fetches top candidate pages in parallel (capped at a concurrency limit of 5 to avoid socket exhaustion).
   - If a page fails (403, 404, timeout), the failure is logged, and a fallback query or secondary URL is used.
3. **Evidence Extraction & Cross-Checking:**
   - Extracts candidate snippets with exact quotes.
   - If a claim appears in only one source, flags it for secondary verification.
4. **Structured Synthesis with Grounded Citations:**
   - Produces an answer where every claim has an explicit bracketed citation ID `[1]`, `[2]` pointing to verified source URLs.
   - Appends an explicit **"Information Gaps & Unverified Claims"** section if data could not be retrieved.

### 5. How the Auditor Should Work

The Auditor must operate under **strict adversarial independence**:
* It **never** receives the Analyst’s scraped cache or scratchpad. It only receives the final drafted text and the list of cited URLs.
* **Process:**
  1. **Claim Extraction:** Breaks down the Analyst's response into atomic factual claims: `(claim_text, cited_url)`.
  2. **Independent Re-Fetch:** Fetches the cited URL itself using the fetcher. If the page is blocked, it attempts an archived copy or secondary search.
  3. **Verification Classification:** Uses strict NLI (Natural Language Inference) prompting to categorize each claim:
     - `SUPPORTED`: The source text explicitly states or directly entails the claim.
     - `CONTRADICTED`: The source text directly conflicts with the claim (e.g., source says "$200M", Analyst claimed "$350M").
     - `UNSUPPORTED`: The source was fetched, but the claimed fact is absent.
     - `NO_CITATION`: A factual claim was made with no citation at all.
  4. **Discrepancy Reporting:** Generates a structured audit report with the exact quote from the source proving or disproving the claim.

### 6. How Memory Should Work (Entity Memory vs. Text Blobs)

Storing raw conversation history as text blobs fails because it inflates prompt tokens, pollutes context with outdated web text, and doesn't scale.

Instead, we use a **Structured SQLite Entity-Fact Memory**:

```sql
-- Schema Overview
CREATE TABLE entities (
    entity_id TEXT PRIMARY KEY,
    name TEXT,
    category TEXT, -- e.g., 'quick_commerce', 'jewellery_retail'
    created_at TIMESTAMP
);

CREATE TABLE entity_facts (
    fact_id TEXT PRIMARY KEY,
    entity_id TEXT,
    attribute TEXT, -- e.g., 'head_of_engineering', 'latest_funding_round', 'store_count'
    value TEXT,
    source_url TEXT,
    verified_at TIMESTAMP,
    FOREIGN KEY(entity_id) REFERENCES entities(entity_id)
);
```

### 7 & 8. Web Search, Page Fetching & Inaccessible Page Handling

Web fetching must handle real-world failures cleanly rather than crashing:

| Failure Type | Detection Mechanism | System Action & Logging |
| :--- | :--- | :--- |
| **HTTP 403 / 401 / Cloudflare** | Status code `403` or challenge HTML | Mark `BLOCKED_BY_BOT_WALL`. Log status. Do not retry domain; fall back to news aggregator or secondary domain. |
| **HTTP 404 / 410** | Status code `404` | Mark `URL_NOT_FOUND`. Remove from citation candidates. Trigger alternative search query. |
| **Timeout / Connect Error** | `httpx.TimeoutException` (>5s) | Fast-fail after 1 backoff retry. Mark `FETCH_TIMEOUT`. Prevent blocking the 2-minute overall ceiling. |
| **JS-Only SPA (Empty HTML)** | HTML body < 300 bytes or `<div id="app"></div>` with no text | Detect empty extraction. Mark `JS_RENDER_REQUIRED`. Use search API snippet fallback instead of hallucinating content. |
| **Contradictory Sources** | Two sources provide conflicting numbers | Analyst extracts both numbers, highlights the disagreement, and justifies why one is more recent or authoritative (e.g., official quarterly filing vs. speculative news leak). |

**Crucial Auditor Catch:** If the Analyst makes a claim citing a URL that returned a `403` or `404`, the Auditor will catch this immediately as `UNSUPPORTED` (flagging a potential hallucination).

### 13. Critical Risks & Subtle Gotchas to Watch Out For

1. **The 2-Minute Wall-Clock Ceiling:**
   - If web scraping is done sequentially (e.g. 8 pages $\times$ 4s = 32s + LLM generation), questions with multiple sources will easily time out. **Parallel asynchronous fetching is mandatory.**
2. **Auditor Context Poisoning:**
   - If the Auditor is given the text snippet that the Analyst extracted, the Auditor isn't auditing the live web—it's just auditing the Analyst's reading comprehension. The Auditor **must** fetch the raw URL itself.
3. **Over-scraping & Context Overflow:**
   - Scraped HTML pages can be 50,000+ tokens. Raw HTML must pass through `trafilatura` or snippet extraction before entering LLM context to prevent token bloat and runaway costs.
4. **Honest Inadequacy Reporting:**
   - LLMs hate admitting they couldn't find something. The system prompt must reward returning `"UNVERIFIED: Source returned 403 Forbidden"` over a plausible guess.
